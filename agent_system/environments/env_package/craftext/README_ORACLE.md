# Craftext с поддержкой Oracle

Эта модификация добавляет возможность агенту задавать вопросы оракулу во время обучения в среде Craftext.

## Описание

В этой модификации агент может задавать вопросы оракулу (необучаемому агенту), который помогает ему понимать состояние игры, планировать действия и отвечать на вопросы о механиках игры.

## Архитектура

1. **Oracle Agent** (`oracle.py`): Ray remote actor, который загружает Qwen 2.5 1.5B модель и отвечает на вопросы. Веса модели хранятся только в одном экземпляре оракла, что позволяет избежать дублирования при распараллеливании.

2. **CraftextWorkerOracle** (`envs_oracle.py`): Модифицированный воркер, который обрабатывает вопросы в методе `step()`.

3. **CraftextMultiProcessEnvOracle** (`envs_oracle.py`): Векторизованная среда с поддержкой оракла.

4. **CraftextOracleEnvironmentManager** (`env_manager.py`): Менеджер окружения, который обрабатывает вопросы и включает ответы оракла в наблюдения.

5. **craftext_projection_oracle** (`projection_oracle.py`): Функция проекции, которая извлекает действия и вопросы из текстового вывода LLM.

## Использование

### Конфигурация

В конфигурационном файле укажите имя среды с суффиксом `Oracle`:

```yaml
env:
  env_name: "craftext/CraftextOracleEnv"  # или "craftext/CraftextOracleVLEnv" для визуальной версии
  craftext_settings: "achievements_collect_wood"
  oracle_model_name: "Qwen/Qwen2.5-1.5B-Instruct"  # опционально, по умолчанию используется Qwen2.5-1.5B
```

### Формат ответа агента

Агент должен использовать следующий формат для действий с вопросами:

```xml
<question>your question here (optional)</question>
<action>your_action_here</action>
```

Вопрос опционален - агент может выполнять действия без вопросов.

### Примеры вопросов

- "How do I collect wood?"
- "What should I do next?"
- "Where can I find stone?"
- "How do I make a pickaxe?"

## Требования

- `transformers` библиотека для работы с моделями
- `torch` для работы с моделями
- `ray` для распараллеливания

Установка:
```bash
pip install transformers torch
```

## Особенности реализации

1. **Распараллеливание**: Оракла создается как один Ray remote actor, который используется всеми воркерами. Это позволяет избежать дублирования весов модели.

2. **Асинхронность**: Вопросы к оракулу обрабатываются через Ray remote calls, что позволяет эффективно использовать ресурсы.

3. **Контекст**: Оракул получает контекст текущего состояния игры (задача и текущее состояние), что помогает ему давать более релевантные ответы.

## Отличия от базовой версии

- Добавлена поддержка тега `<question>` в ответах агента
- Ответы оракла включаются в наблюдения агента
- Используется отдельная projection функция `craftext_projection_oracle`
- Используется отдельный EnvironmentManager `CraftextOracleEnvironmentManager`
